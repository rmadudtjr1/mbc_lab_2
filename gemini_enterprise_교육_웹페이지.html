전 직원이 Gemini Enterprise로 자기 업무의 반복 작업 1개 이상을 자동화하는 것을 목표로 합니다. 각 장의 이론 뒤에 관련 실습이 바로 이어집니다 — 배운 내용을 그 자리에서 직접 해봅니다.

1. Skills — Gemini Enterprise에서의 역할과 사용 범위

1주차 복습 Skills는 1주차에 학습한 내용입니다. 2주차에서는 본 교육(Agent Designer)에 앞서, 실무 적용의 기준이 되는 핵심 — Skills의 역할과 사용 가능 범위 — 를 복습으로 간단히 정리하고 시작합니다.

Gemini Enterprise 안에서의 역할

Skill은 자주 쓰는 지시·절차·참고 지식을 패키지로 저장해 대화에서 재사용하는 기능입니다. 프롬프트의 "규칙 부분"을 자산화한 것입니다.

Skills는 ③상호작용 층에 속합니다. 즉 검색·채팅이 답을 만드는 방식(형식·문체·규칙)을 표준화하는 계층이지, 스스로 일을 수행하는 에이전트(④층)가 아닙니다. 이 위치가 Skills의 역할과 한계를 동시에 결정합니다.

  • 역할 1 — 출력 표준화: 자막 규격, 기사 문체, 표기법을 매번 동일하게
  • 역할 2 — 사내 규칙 적용: MBC 방송 언어 가이드 등 반복 규칙 자동 반영
  • 역할 3 — 프롬프트 자산화: 반복 입력 제거, @이름 호출 또는 자동 활성화, 팀 공유

어디까지 사용 가능한가 — 경계표

판단 기준은 하나입니다: "이 작업이 대화 안에서 완결되는가?" Skills는 모델이 어떻게 답할지를 바꿀 뿐, 모델 밖의 시스템을 실행하지 못합니다.

3. 통합 검색 — RAG의 원리

통합 검색은 RAG(검색 증강 생성) 구조로 동작합니다.

이 구조를 이해하면 세 가지가 설명됩니다.

  • 왜 출처 인용이 달리는가 — 답변이 ①에서 찾은 문서에 근거하기 때문
  • 왜 권한 없는 문서는 안 나오는가 — ①단계에서 ACL 필터가 걸리기 때문
  • 왜 최신 문서가 안 보일 때가 있는가 — 인덱스는 커넥터 동기화 주기로 갱신되기 때문

시맨틱 검색 vs 키워드 검색

키워드 검색은 단어 일치, 시맨틱 검색은 의미 일치입니다. "PPL 노출 기준"으로 검색해도 "간접광고 규정" 문서를 찾습니다. 따라서 질의는 문장형으로 작성합니다.

검증 습관 (방송사 필수) 인용 번호 클릭 → 원문 대조 → 문서 최종 수정일 확인. AI 답변은 초안이며 출고 전 사람이 검증합니다.

콘솔 사용하기 — AI Assistant

  • 대화 이력: 대화는 '최근' 탭에 60일간 저장되며, 검색 버튼으로 지난 대화를 찾고 세션 형태로 이어서 진행할 수 있습니다
  • 파일 추가: 로컬 파일·Google Drive·OneDrive 파일을 업로드하고, 웹 이미지를 복사해 바로 붙여넣을 수 있습니다 (여러 파일 동시 선택 가능)
  • Omnibar(입력창): 이미지·동영상·코드 등 모든 종류의 파일을 입력창으로 끌어다 놓으면 바로 분석·대화가 시작됩니다
  • @ 참조: @ 기호로 에이전트와 파일을 손쉽게 호출해 상호작용합니다 (Skill 호출과 같은 방식)
  • 프롬프트 칩: 입력창의 '이메일 초안 작성', '데이터 분석/시각화' 등 칩을 클릭하면 세부 프롬프트 예시가 나타납니다
  • 후속 질문(follow-ups): 답변의 특정 부분을 선택·인용해 다음 질문에 포함시키면 문맥을 유지하며 깊이 있는 대화를 이어갈 수 있습니다

웹 검색 (Web Search)

Google 웹 검색 결과를 답변 소스로 활용해 가장 최신의 정확한 정보를 제공합니다.

  • 입력창의 'Sources' 메뉴에서 웹 검색을 켜고 끌 수 있습니다 (관리자가 허용한 경우 기본 활성화)
  • 공개된 웹사이트 URL을 붙여넣기만 하면 해당 페이지 콘텐츠에 대해 바로 대화할 수 있습니다 (접근 차단 사이트는 제외)
  • 웹 검색 답변에는 출처 웹사이트가 함께 표시됩니다 — 사내 검색의 인용과 같은 검증 습관을 적용합니다
  • 활용 예: "MBC 관련 최신 뉴스를 요약해 줘", "경쟁 방송사의 최근 편성 변화를 파악해 줘"

실습 1 · 로그인과 첫 검색

30분이론 3장난이도 ★

목표: 콘솔 화면에 익숙해지고, 사내 검색·웹 검색의 답변을 출처 인용으로 검증하는 습관을 만듭니다. 방송사에서 가장 중요한 훈련입니다 — AI 답변은 초안이며 검증은 사람의 몫입니다.

1-1. 접속과 화면 익히기 (5분)

  1. Chrome에서 안내된 URL 접속 → 회사 계정 로그인 (개인 Gmail 금지 — 기업 보호가 적용되지 않습니다)
  2. 화면에서 다음 3가지를 직접 찾아봅니다: ① Omnibar(중앙 입력창)와 그 아래 프롬프트 칩 ② 좌측 '최근' 탭 — 대화가 60일간 저장되는 곳 ③ 입력창의 'Sources' 메뉴 — 웹 검색을 켜고 끄는 곳
  3. Omnibar에 @를 입력해 에이전트·파일 참조 목록이 뜨는 것을 확인합니다 (호출은 다음 실습에서)

1-2. 첫 사내 검색 + 인용 검증 (10분)

PROMPT · 사내 검색
어린이 프로그램에서 간접광고가 허용되는지 규정 근거와 함께 알려줘

7. 에이전트 개발 스펙트럼 — No-code / Low-code / Pro-code

"어떤 도구로 만들 것인가"는 개발 방식 스펙트럼 위에서 결정됩니다. 도구 선택 기준을 먼저 잡아두면 이후 실습과 실무 적용이 훨씬 수월해집니다.

7.1 No-code — 대화형 에이전트 (Agent Designer)

코드 없이 클릭과 자연어만으로 에이전트를 제작·배포하는 빌더입니다.

구성역할예 (제작발표회 브리핑 에이전트)
지시문목표·절차·말투·금지사항"프로그램명 → 자료 검색 → 요약 → 예상 질문 5개"
지식근거로 삼을 데이터 소스Drive 실습_보도자료 폴더
도구검색·생성 외 수행 동작웹 검색, 캘린더 조회(승인 시)
시작 프롬프트사용자에게 보일 예시 버튼"신작 드라마 OOO 브리핑해줘"

설계 원칙 4가지: ①한 가지 일만 잘하게 ②데이터 소스 최소화 ③"모르면 모른다" 명시 ④출처 인용 필수화

Skills와의 결정적 차이: 데이터 소스 연결 + 다단계 처리 + 갤러리 배포. 한계: 조건 분기·루프 등 코드 수준 제어 불가, 외부 쓰기 작업은 제공 액션 범위 내에서만.

7.2 Low-code — 워크플로 에이전트 (Agent Designer)

대화형 에이전트가 "물으면 답하는" 방식이라면, 워크플로 에이전트는 정해진 시간이나 이벤트에 스스로 실행되는 자동화입니다. 코드를 직접 짜지는 않지만 트리거·노드·API를 다루므로 Low-code 성격을 가지며, 주 사용자는 AX 챔피언(8장 역할 모델)입니다.

  • 트리거: 스케줄링(정해진 시간), 채팅, 이메일·커넥터 이벤트 기반 실행
  • 노드 결합: 규칙 기반(결정적) 흐름 안에 AI(비결정적) 노드와 HITL(사람 승인) 노드를 삽입
  • 커스텀 확장: REST API 노드, BYO MCP — 사내 시스템·외부 서비스 연결 (이 지점이 Low-code의 핵심)
  • 편집: 비주얼 에디터(GUI) 또는 채팅 에디터 — 상세 기능은 7.7 참조

예 (공식): "주간 AI 뉴스레터 비서" — 월요일 오전 9시 트리거 → Gmail에서 메일 찾기 → 내용 요약 → 보고서 발송.
MBC 예: "아침 이슈 브리핑 자동 발송" — 평일 오전 6시 트리거 → 밤사이 뉴스·사내 소스 검색 → 요약 → 데스크 승인(HITL) → 부서 메일 발송.

7.3 Pro-code — ADK · A2A · Antigravity 3주차 · 배경 설명

아래 내용은 3주차에 자세히 다루며, 2주차에서는 전체 그림 이해를 위한 배경으로만 소개합니다. 완전한 코드 제어가 필요할 때의 영역입니다. 워크플로 에이전트의 노드로도 부족한 커스텀 로직·멀티 에이전트·시스템 통합은 ADK(Agent Development Kit)로 직접 개발합니다.

# ADK 에이전트의 최소 구조 (개념 예시)
from google.adk.agents import Agent

subtitle_agent = Agent(
    name="subtitle_agent",
    model="gemini-3.7-flash",
    instruction="리포트 원고를 21자×3줄 자막으로 변환한다...",
    tools=[search_articles, check_style_guide],  # 커스텀 함수를 도구로 연결
)
  • instruction = Agent Designer의 지시문과 같은 개념 — 이론이 그대로 이어집니다
  • tools = 파이썬 함수를 도구로 등록 — 내 시스템의 API를 함수로 감싸 자유롭게 연결
  • MBC 예: 보도정보시스템 조회 함수를 도구로 등록한 "기사 이력 조회 에이전트"
요소역할
ADK 심화멀티 에이전트 오케스트레이션, 상태 관리, 평가(eval), 배포
A2A서로 다른 플랫폼의 에이전트끼리 표준 프로토콜로 호출·협업
Antigravity에이전틱 IDE — AI가 코드를 작성·실행·검증, 개발자는 감독자
Agent Engine완성한 에이전트를 관리형 인프라에 배포·운영

Antigravity의 위치: GE 화면 "안"의 도구가 아니라, 화면 "밖"에서 돌아갈 것(앱·배치·API 연동)을 만드는 개발 환경입니다 (3주차). Pro-code로 만든 에이전트도 등록을 거쳐 GE 갤러리에 게시되므로 만드는 방식은 달라도 쓰는 곳은 하나입니다.

④ 실행 (Action)판단 결과를 바탕으로 실제 세계에 변화(Write/Update)를 일으킴
  • CoT (Chain of Thought): 결론 전에 '단계별로 생각'하도록 유도해 추론 능력 극대화 — 수학 문제를 암산 대신 풀이 과정을 적으며 푸는 것과 같습니다
  • ReAct (Reasoning + Acting): 생각(Thought) → 행동(Action) → 관찰(Observation)의 루프를 돌며 목표를 향해 나아갑니다. 예: "주문 번호가 필요하다"(생각) → DB 검색 도구 실행(행동) → "주문 #12345, 배송 완료"(관찰) → 다음 판단

7.6 업무 기반 에이전트 설계 3단계

  1. Task Decomposition — '모호한 지시'를 실행 가능한 최소 단위(Micro Steps)로 분해
  2. Tool Definition — 필요한 도구(API/문서)를 계층별로 정의: System of Record(데이터), System of Action(업무 처리), System of Engagement(소통·협업)
  3. Guardrails — 에이전트가 치명적인 실수를 하지 않도록 제약 조건 설정
Human-in-the-Loop (HITL) — 결정적 순간의 안전장치 에이전트의 제안을 최종 승인하는 것은 항상 사람이어야 합니다. 위험도 평가에 따라 저위험(단순 조회·초안 작성)은 자동 실행, 고위험(결재·금액 집행·외부 발송)은 사람의 승인(Approve/Reject)을 거쳐 시스템에 반영합니다. 방송사라면 '기사·자막의 최종 출고'가 대표적인 HITL 지점입니다.

7.7 Agent Designer 상세 기능

  • 자연어·UI 기반 편집: 비주얼 에디터(GUI)와 채팅 에디터 양쪽으로 구축·수정
  • 트리거: 스케줄링(정해진 시간), 채팅, 이메일 및 커넥터 이벤트 기반 실행
  • 결정적 + 비결정적 노드: 규칙 기반(Deterministic) 흐름 안에 AI(Non-deterministic) 노드를 삽입
  • HITL 노드: 사람의 승인·검토·추가 입력 단계를 워크플로우에 포함
  • 커스텀 확장: REST API 노드, BYO MCP 지원
  • 모니터링: Activity details로 에이전트 활동 현황 추적

생성 4단계 (권장 워크플로우): ① Meta Prompting으로 에이전트용 프롬프트 생성 → ② 새 에이전트 만들기에 프롬프트 입력 → ③ 생성된 지시문(Role·Output Expectations) 검토·수정 → ④ 반복 작업이라면 스케줄링 설정. 예: "주간 AI 뉴스레터 비서" — 월요일 오전 9시 → Gmail에서 메일 찾기 → 요약 → 보고서 발송.

7.8 Agent Gallery & Registry — 에이전트의 단일 통합 창구

Gemini Enterprise는 에이전트의 유형·제작자·제작 위치에 관계없이 모든 에이전트를 한곳에서 쓰는 단일 통합 창구(Single Pane of Glass)입니다. Google 기본 제공 에이전트, 파트너 에이전트, 노코드·로우코드·ADK 에이전트가 모두 갤러리에 모입니다.

  • Agent Registry: 개인 에이전트 / 회사 에이전트 / 상용 에이전트를 구분하고 사용 승인 절차로 관리
  • Agent Garden: 샘플 에이전트와 코드 제공 (Low/Pro-code 시작점)
  • 마치 앱 스토어처럼 필요한 기성 에이전트를 탐색해 바로 업무에 적용

실습 4 · 대화형 에이전트 — 제작발표회 브리핑

90분이론 7.1장난이도 ★★★

목표: 지시문 작성 → 테스트 → 수정 반복의 에이전트 제작 사이클을 완주합니다. 이번 실습은 데이터 스토어 연결 없이, 보도자료를 대화에서 직접 제공(붙여넣기 또는 파일 첨부)하는 방식으로 진행합니다. (실제 운영 시 데이터 소스를 연결하는 방식은 7.1장 참고)

4-1. 생성

에이전트 목표 (초안 자동 생성용)
사용자가 보도자료를 붙여넣거나 첨부하면 핵심을 요약하고
예상 기자 질문 5개를 만들어주는 제작발표회 준비 에이전트

생성된 지시문을 아래로 교체합니다.

에이전트 지시문 전문
너는 MBC 홍보팀의 제작발표회 준비 도우미다.

절차:
1. 사용자가 보도자료 텍스트를 붙여넣거나 파일로 첨부하면 그 자료만 분석한다.
2. 자료 없이 프로그램명만 입력하면 "브리핑을 만들려면 보도자료를
   붙여넣거나 첨부해 주세요"라고만 답한다. 기억이나 추측으로 작성 금지.
3. 자료가 제공되면 다음 형식으로 출력한다:

## [프로그램명] 제작발표회 브리핑
### 핵심 요약 (5줄 이내)
### 주요 출연진·제작진
### 예상 기자 질문 5개 (난이도 순, 민감한 질문 최소 1개 포함)
### 근거 (자료의 해당 항목 번호 표기)

규칙: 모든 내용은 제공된 자료에 근거한다. 자료에 없는 내용은 쓰지 않는다.

4-2. 실습 자료 준비

아래 목업 보도자료를 내려받아 둡니다 (가상의 신작 드라마 보도자료): ⬇ 실습데이터_보도자료.txt

파일 내용에는 예상 질문 만들기에 좋은 재료(미확정 사항, 원작 각색 논란 등)가 들어 있습니다.

4-3. 테스트 사이클 — 최소 2회 수정 경험이 목표

#입력확인
1보도자료 파일 첨부(또는 붙여넣기) + 전파왕국 브리핑해줘형식 준수 · 근거 항목 표기 · 민감 질문(원작 각색, OTT 미확정)이 나오는가
2자료 없이 무한도전 브리핑해줘환각 테스트 — 지어내면 지시문 2번 규칙을 맨 위로
3예상 질문을 10개로 늘려줘후속 지시 대응

개인 과제: 본인 업무에서 반복되는 작업 1가지를 골라 그 자리에서 대화형 에이전트로 만들어 봅니다. 조건: 지시문에 출력 형식 명시 + 환각 방지 규칙("자료에 없으면 답하지 않는다") 포함, 테스트 1회 이상.

  • 반복 작업 1가지 선정 완료
  • 지시문에 출력 형식(마크다운 헤더·표 수준까지) 명시
  • 환각 방지 규칙 포함 — 자료 없이 물었을 때 지어내지 않음을 확인
  • 테스트 실행 후 지시문을 1회 이상 수정

막힐 때: 지어냄 → "자료 없이는 답하지 않는다" 규칙을 지시문 맨 위로 · 형식 불안정 → 마크다운 헤더 수준까지 지정 · 첨부 인식 실패 → 파일 대신 본문 붙여넣기로 시도.

실습 5 · 워크플로 에이전트 — 아침 이메일 브리핑 자동화

60분이론 7.2장난이도 ★★★

목표: 트리거 → 실행 → 사람 확인(HITL)으로 이어지는 워크플로 에이전트를 완성합니다. 대화형 에이전트(실습 4)가 "물으면 답하는" 것이었다면, 이번에는 정해진 시간에 스스로 실행되는 자동화를 만듭니다.

5-1. Meta Prompting으로 에이전트 프롬프트 생성 (10분)

워크플로 지시문을 직접 쓰지 않고, AI에게 설계를 맡깁니다 (5장 Meta Prompting의 실전 적용).

PROMPT · META PROMPTING
email을 정리해서 유형별로 분류하고, 테이블 형태로 출력하는
Gemini Enterprise 에이전트를 생성할 수 있는 프롬프트를 작성해줘.
포함할 것: 분류 유형(긴급/일정/단순 알림/뉴스레터), 각 메일의
발신자·제목·핵심 요약·우선순위·필요 조치 추출, 마크다운 표 출력,
상단에 총 메일 수와 우선순위별 건수 표시, 한국어 응답.

생성된 프롬프트를 검토합니다 — 역할(Role)과 출력 기대(Output Expectations)가 갖춰졌는지 확인하고, 마음에 안 드는 부분은 후속 지시로 다듬습니다.

5-2. 워크플로 생성 (15분)

  1. Agent Designer → 새 에이전트 만들기 → 5-1에서 만든 프롬프트를 붙여넣습니다
  2. 자동 생성된 작업 단계를 확인합니다: Gmail에서 메일 찾기 → 분류·요약 → 보고서 작성
  3. 생성된 지시문(Role · Output Expectations)을 열어 요청 사항이 반영됐는지 검토하고, 빠진 규칙은 직접 수정합니다 — 비주얼 에디터와 채팅 에디터 둘 다 써봅니다

5-3. 트리거 설정 — 스케줄링 (10분)

  1. 트리거를 평일 오전 8시 50분 스케줄로 설정합니다 (아침 회의 전 브리핑 도착)
  2. 트리거 종류를 살펴봅니다: 스케줄 외에 채팅·이메일·커넥터 이벤트로도 실행 가능함을 확인

5-4. HITL 노드 — 사람의 승인 넣기 (10분)

보고서 마지막에 "단순 알림·뉴스레터를 지금 읽음 처리할까요?"라고 사용자에게 확인을 요청하고, 승인했을 때만 처리하도록 단계를 추가합니다. — 조회·요약(저위험)은 자동, 변경 작업(읽음 처리)은 사람 승인 후라는 HITL 원칙(7.6장)을 워크플로에 직접 구현하는 단계입니다.

5-5. 테스트와 모니터링 (10분)

  1. 스케줄을 기다리지 말고 수동 실행으로 즉시 테스트합니다
  2. 결과 보고서의 분류·표·우선순위 건수가 요구대로 나오는지 확인 → 미흡하면 지시문 수정 후 재실행 (최소 1회 수정 사이클)
  3. Activity details에서 실행 이력·각 단계의 동작을 확인합니다 — 운영 시 문제 추적 지점
  • Meta Prompting으로 에이전트 프롬프트 생성
  • 자동 생성된 단계·지시문 검토 및 1회 이상 수정
  • 스케줄 트리거 설정 완료
  • HITL 확인 단계 추가 완료
  • 수동 실행 테스트 + Activity details 확인

개인 과제: "정해진 시간마다 반복하는" 본인 업무 1개를 워크플로로 제작 (예: 주간 보고 초안, 게시판 모니터링 요약). 조건: 트리거 + HITL 단계 각 1개 이상 포함.

  • 정기 반복 업무 1개 선정
  • 스케줄(또는 이벤트) 트리거 설정
  • HITL(사람 승인) 단계 1개 이상 포함
  • 수동 실행 테스트 + Activity details 확인

막힐 때: 단계가 이상하게 생성됨 → 5-1 프롬프트에 작업 순서를 명시 · Gmail 연결 안 됨 → 커넥터 승인 상태 확인 · 읽음 처리가 바로 실행됨 → HITL 단계가 처리 단계 앞에 있는지 순서 확인.

부록 실습 · Skill 만들기 — 자막-요약 (1주차 과정)

50분이론 1장신규 참석자용

1주차에 진행한 실습의 전문입니다. 신규 참석자의 따라잡기와 복습용으로 수록합니다 — 반복 지시를 Skill로 패키지화하고, Skills의 범위 한계를 직접 체감합니다.

A-1. 생성 (공식 절차)

  1. 탐색 메뉴에서 Skills 클릭 → 추가 아이콘 → Create skill with Gemini 선택
  2. 이름: 자막-요약
  3. 설명: 뉴스 리포트 원고를 방송 자막 규격(21자×3줄)으로 변환할 때 사용 — 설명은 Gemini가 이 Skill의 사용 여부를 판단하는 트리거 기준이 됩니다
  4. 지침은 Markdown 직접 편집으로 아래 전문을 붙여넣고 Save — 저장하면 기본적으로 자동 활성화됩니다

웹 앱 편집기로는 단일 SKILL.md 스킬만 만들 수 있습니다. 스크립트(Python·Bash)가 필요한 복잡한 Skill은 루트에 SKILL.md를 둔 ZIP 번들로 업로드합니다.

SKILL 지시문 전문
너는 MBC 뉴스 자막 담당자다. 입력된 리포트 원고를 자막으로 변환한다.

규칙:
1. 한 줄 21자 이내(공백 포함), 최대 3줄로 출력한다.
2. 존댓말·서술형 어미를 제거한다. ("참석했습니다" → "참석")
3. 숫자는 아라비아 숫자로 쓴다. ("이백여 명" → "200여 명")
4. 각 줄은 독립적으로 읽혀도 뜻이 통해야 한다.
5. 원고에 없는 사실을 추가하지 않는다.
6. 마지막에 각 줄의 글자 수를 괄호로 표시한다.

예시 입력: "오늘 오전 열린 개막 행사에는 관계자 200여 명이 참석했습니다."
예시 출력:
개막 행사에 200여 명 참석 (15)

A-2. 테스트

새 대화에서 @자막-요약 호출 후 입력:

실습 데이터 · 가상 리포트 원고
오늘 오전 서울 마포구 상암동 일대에서 열린 드론 배송 시범 사업 개막
행사에는 국토교통부 관계자와 지방자치단체장 등 200여 명이 참석했습니다.
이번 시범 사업은 내년 상반기까지 진행되며, 상암동 일대 아파트 단지와
오피스 건물을 대상으로 주 5회 생활용품 배송이 이뤄질 예정입니다.

예상 결과 (유사하면 성공):

상암동서 드론 배송 시범사업 개막 (17)
국토부 등 200여 명 참석 (13)
내년 상반기까지 주 5회 배송 (15)
